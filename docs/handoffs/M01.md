# M01 Handoff

## Established

- `chem_wiki.modules.chemistry_core` 是 M01 的唯一公共入口，导出冻结范围内的
  29 个实体和值对象类型。
- 已实现强类型 ID 与最小 `ProvenanceRef`，没有抽取全局 `shared/common`。
- 已实现 `Element`、`Substance`、`Ion`、`Structure`、`FunctionalGroup`，其中
  `Structure` 与 `Substance` 保持独立。
- 已实现一等 `Reaction` 聚合；`ReactionParticipant` 具有稳定 ID，target 严格为
  `SubstanceId | IonId`，并执行参与者 ID 唯一、至少一个 reactant 和一个 product、
  计量系数大于零等冻结不变量。
- `Condition` 保持为 Reaction 内嵌值对象。领域实现只依赖 Python 标准库和 M01
  内部模块。
- 边界守卫同时约束 M01 内部依赖和未来跨模块导入；跨模块源码不得直连
  `chemistry_core` 内部文件。

## Boundaries and deferred work

- 未实现通用 `ChemicalSpecies` 层次、repository、service、Port、adapter、ORM
  mapping、API DTO 或数据库迁移。
- Structure 解析、化学有效性验证、规范化、指纹、结构比较、渲染及官能团检测均
  延期，M01 未引入 RDKit 或其他化学库。
- `KnowledgeEdge`、`ContentSource`、`ContentRevision`、`Experiment`、
  `Phenomenon`、`Concept`、`Question`、`ExamTag` 和 `ExamOccurrence` 由后续模块拥有。
- `AtomMapping`、`BondDiff`/`BondChange`、`Mechanism`、`MechanismStep`、
  `ElectronFlow`/`ElectronMove` 完全延期，没有建立占位类型。后续必须继续保持
  Atom Mapping、Bond Diff 与 Reviewed Mechanism 分层，不能从 atom mapping 推断
  mechanism 为真。
- 跨模块消费者只能从 `chem_wiki.modules.chemistry_core` 包根导入；内部文件不是
  稳定公共契约。
