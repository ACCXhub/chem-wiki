# M03 Handoff

## Established

- 仓库根级 `AGENTS.md` 是项目规则的 canonical 基线：模块职责保持局部、跨模块只经
  公共入口、禁止推测性 `shared/common` 抽象，并要求以聚焦验证完成闭环。
- 前端 `frontend/src/modules/periodic_table/` 是 M03 唯一 UI owner。它显示 canonical
  1–118 周期表布局、原子序数、符号与中文名，并按元素类别着色。
- UI 支持 hover preview、点击选择、键盘焦点、中文名/英文名/符号/原子序数搜索定位，
  以及电负性和第一电离能热力图。缺失的 canonical 属性明确显示为“暂无数据”。
- 后端 `chem_wiki.modules.periodic_table` 是 M03 read-model 与 HTTP owner。它从 M02
  的 PostgreSQL canonical 表读取元素和已发布的物化属性，生成 source-neutral DTO；
  不向前端暴露 raw payload、claim 或 source record schema。
- 118 元素布局、类别和区块由 M03 后端根据原子序数生成，前端不重复硬编码元素数据。
  所有当前 canonical 元素以 `confirmed` 状态返回；DTO 为未来受支持的 `predicted`
  状态保留了稳定字段。

## Module and API boundaries

- M03 对后端的公共入口是 `chem_wiki.modules.periodic_table`；它只从
  `chem_wiki.modules.element_data` 包根导入 M02 persistence mapping。
- `GET /v1/elements` 返回元素 UUID、identity、类别、布局、状态，以及
  `electronegativity` / `firstIonizationEnergy` 的值和单位。属性只有在 M02 存在相应
  published selection 时才会输出值。
- `frontend/src/app/App.tsx` 只装配 M03 public module；fetch client、DTO、交互状态与 CSS
  都留在 `periodic_table` 内部。Vite 仅代理 `/v1` 到本地 backend。

## M04 extension point

- 元素选择使用 M01/M02 保留的稳定 UUID。`PeriodicTableView` 提供
  `onElementSelect(elementId)`，元素按钮也保留 `data-element-id`。
- 当前仅显示“Element Wiki 将在 M04 通过当前元素 ID 接入”的状态提示；没有 Wiki 路由、
  Wiki 正文、来源资产或 M04 数据模型。
