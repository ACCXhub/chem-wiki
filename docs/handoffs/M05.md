# M05 Handoff

## Established

- `chem_wiki.modules.reaction_core` 是 M05 Reaction Core 的唯一后端公共入口。它只从
  M01 `chemistry_core` 包根导入冻结的 Reaction、participant、condition、provenance
  类型；M01 `Reaction` 继续是一等聚合，而非 Substance 到 Substance 的图边。
- Reaction 保持稳定 UUID identity；参与者以 M01 `ReactionParticipantId` 作为独立稳定
  UUID，显式保存 `substance | ion` target type、reactant/product 等角色、精确计量系数
  与已冻结 phase。一个 Reaction 可具有多个 reactant 和 product，未被折叠为 pairwise
  relation。
- M05 PostgreSQL owner 包含 `reaction`、`reaction_participant`、`reaction_condition`、
  `reaction_source`、`reaction_phenomenon` 与 `reaction_phenomenon_source`。repository
  负责 Reaction document 的写入与读回；migration
  `20260824_02_m05_reaction_core` 是该 schema 的 canonical 建立点。
- 发布反应必须有守恒通过的方程式、经审核的 reaction provenance、审核人和审核时间。
  发布的现象事实同样要求字段级来源。redox metadata 只能作为审核事实持久化，不能由方程
  式自动推断。

## Equation Lab

- `POST /v1/reactions/balance` 是 M05 Equation Lab 的最小 HTTP 边界；它接收 molecular、
  ionic 或 net_ionic 方程输入，返回 display DTO、最简系数、元素守恒、适用时的总电荷守恒，
  并明确返回输入已配平、输入未配平、无效或无净离子反应状态。
- `frontend/src/modules/equation_lab/` 是前端唯一 owner；`/equation-lab` 提供方程输入、
  冻结示例、配平方程显示、守恒表与明确的机制边界提示。它通过 M05 API 调用，不依赖
  persistence schema。
- 支持的净离子范围仅包括当前冻结的 AgCl 沉淀显示和 Na+ / NO3- 无净离子反应示例；不会
  为缺少审核规则的反应虚构生成物或现象。

## Balancing and conservation

- 配平 engine 使用 Python 标准库 `Fraction` 的精确有理数零空间计算，并归一为最简正整数
  系数；不使用浮点算术。方程 parser 支持当前 M05 范围内的元素式、括号、phase 与离子
  charge 表示。
- SymPy 1.14（BSD）和 ChemPy 0.10.1（BSD-2-Clause）均经许可证、维护与适配性评估。
  对当前小范围功能而言，其依赖面和架构成本大于收益，因此未新增依赖。engine 保持在
  `reaction_core.equation` 的窄边界内，未来可替换而不改变 Reaction 领域语义。

## Preserved boundaries and deferred work

- Atom Mapping、Bond Diff/Bond Change、Mechanism、MechanismStep、Electron Flow 均未
  建立类型、表或推断逻辑；特别是不从 equation 或 balancing 推断机制真值。
- M09 Reaction Sphere、Reaction Map、通用 graph framework 与空间行为均未开始。
- M10 Synthesis、路线搜索和配方推荐均未开始。
- 通用溶解度规则、从分子方程式自动拆解净离子方程式、自动氧化数或氧化还原解释均超出
  当前 M05 最小范围。
