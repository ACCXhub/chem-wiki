# M05 Handoff

## Established

- `chem_wiki.modules.reaction_core` 是 M05 Reaction Core 的唯一后端公共入口。它只从
  M01 `chemistry_core` 包根导入冻结的 Reaction、participant、condition、provenance
  类型；M01 `Reaction` 继续是一等聚合，而非 Substance 到 Substance 的图边。
- Reaction 保持稳定 UUID identity；参与者以 M01 `ReactionParticipantId` 作为独立稳定
  UUID，显式保存 `substance | ion` target type、reactant/product 等角色、精确计量系数
  与已冻结 phase。一个 Reaction 可具有多个 reactant 和 product，未被折叠为 pairwise
  relation。
- M05 PostgreSQL owner 包含 `reaction`、`reaction_participant`、`reaction_condition`、
  `reaction_source`、`reaction_phenomenon` 与 `reaction_phenomenon_source`。repository
  负责 Reaction document 的写入与读回；migration
  `20260824_02_m05_reaction_core` 是该 schema 的 canonical 建立点。
- 发布反应必须有守恒通过的方程式、经审核的 reaction provenance、审核人和审核时间。
  发布的现象事实同样要求字段级来源。redox metadata 只能作为审核事实持久化，不能由方程
  式自动推断。

## Equation Lab

- `POST /v1/reactions/balance` 是 M05 Equation Lab 的最小 HTTP 边界；它接收 molecular、
  ionic 或 net_ionic 方程输入，返回 display DTO、最简系数、元素守恒、适用时的总电荷守恒，
  并明确返回输入已配平、输入未配平、无效或无净离子反应状态。
- `frontend/src/modules/equation_lab/` 是前端唯一 owner；`/equation-lab` 默认提供结构化
  Equation Composer。其轻量 application/UI draft 显式保存 molecular / ionic / net-ionic
  mode、reactants、products，以及所选 catalog/application identity、entity kind、名称、化学式、
  电荷、分类、equation suitability 与用户选定物态；它不是新的 chemistry domain model。
- Composer 通过 `GET /v1/catalog/species` 使用 `knowledge_catalog` 拥有的中文名、alias、
  英文/search token、ASCII formula、canonical category、Palette rank 与 equation-mode suitability。
  单质、酸、碱、盐、氧化物、阳离子、阴离子等导航只是既有 canonical category 的展示映射，
  前端不持有重复物种数据库。
- Equation Lab 的当前工作台以“物质”作为可见术语：搜索、收藏、最近和受控 Builder 解析到的
  `CatalogSpecies` 都复用同一个紧凑、可换行的 module-local 物质块。整块可拖放，桌面工作台
  sticky 固定在物质库上方；工作台上半部按左右两半进行宽磁吸捕获，左侧为反应物、右侧为生成物。
  同一物质在同一侧只保留一个 participant（以配平系数表达倍数），但可在方程两侧各出现一次。
- 已放入的 participant 可拖到另一侧或同侧重排；跨侧遇到既有相同 identity 时收敛为一个目标侧
  participant。单击/Enter/Space 打开紧凑的上下文物态选择（`—`、`(s)`、`(l)`、`(g)`、`(aq)`），
  双击/Delete/Backspace 移除。原生拖放有 movement threshold，拖动不会触发物态 UI；窄屏用临时
  “放入反应物 / 放入生成物”控件替代精确拖放。
- 前端保留有界的 `EquationDraft` 用户历史：添加、移动、重排、物态、移除和清空均支持撤销/重做
  （按钮、Ctrl+Z、Ctrl+Shift+Z），异步配平响应不写入历史。草稿通过既有 serialization 交给
  M05 配平边界；自动配平使用短暂 debounce 并以请求序号拒绝过期响应，作为工作台中的可展开工具。
  关闭自动配平时仍可用同一既有 M05 boundary 手动配平；当前方程文本可复制为笔记用文本。
- 同一 catalog read model 还以只读 DTO 暴露 `composition` 与
  `chemicalClassifications`。`GET /v1/catalog/species/completions` 按 composition、已选计数满足度、
  原子缺口、额外元素/原子、方程适用性、教学优先级与 Palette rank 稳定返回已有候选；原
  `GET /v1/catalog/species` 精确 lookup 保持不变。`knowledge_catalog` 仍是单一 species owner，
  未建立第二套目录。
- Palette 默认仍是直接搜索与既有 category/mode 排序。Equation Lab 可在本地、版本化的
  `localStorage` 偏好中保存 application ID 形式的收藏与最近使用记录；保存 ID 通过同一
  `GET /v1/catalog/species` read model 的小批量精确 lookup 独立回填，并以紧凑的收藏/最近
  quick-access 展示，不污染正常搜索或分类结果，不持久化到帐户/数据库，失效 ID 安全移除。
- 受控 Species Builder 仅把 M03 public element API 的元素块和 catalog 的阳/阴离子块放入计数
  tray，聚合 composition 后查询已有 substance completion。零、一、多个候选均为显式状态；
  tray 的 partial charge 不会排除中性完成候选，不匹配不会生成 Substance/Ion identity。元素块
  暂不可用时，catalog 离子块仍可独立使用并明确提示。
- 草稿序列化为既有 M05 parser 接受的方程字符串后调用 `POST /v1/reactions/balance`。Equation Lab
  的 `ChemistryNotation` 是 KaTeX + mhchem 的窄显示 adapter，用于系数、下标、电荷、物态与箭头，
  不改写 EquationDraft、catalog identity 或 Reaction DTO。高级直接文本输入保留为折叠 fallback，
  不再是默认工作流。
- 现有配平结果、守恒表、invalid error、already-balanced、unbalanced-and-solved 与
  no-net-ionic 状态保持不变；Equation Lab 仍只消费 M05 HTTP DTO，不依赖 persistence schema。
- 支持的净离子范围仅包括当前冻结的 AgCl 沉淀显示和 Na+ / NO3- 无净离子反应示例；不会
  为缺少审核规则的反应虚构生成物或现象。

## Balancing and conservation

- 配平 engine 使用 Python 标准库 `Fraction` 的精确有理数零空间计算，并归一为最简正整数
  系数；不使用浮点算术。方程 parser 支持当前 M05 范围内的元素式、括号、phase 与离子
  charge 表示。
- SymPy 1.14（BSD）和 ChemPy 0.10.1（BSD-2-Clause）均经许可证、维护与适配性评估。
  对当前小范围功能而言，其依赖面和架构成本大于收益，因此未新增依赖。engine 保持在
  `reaction_core.equation` 的窄边界内，未来可替换而不改变 Reaction 领域语义。

## Preserved boundaries and deferred work

- Atom Mapping、Bond Diff/Bond Change、Mechanism、MechanismStep、Electron Flow 均未
  建立类型、表或推断逻辑；特别是不从 equation 或 balancing 推断机制真值。
- M06 Ketcher/RDKit Structure Lab 保持独立；Ketcher reaction arrow、reaction-plus 与 mapping
  工具仍由 M06 adapter 隐藏，未作为普通方程 Composer，也未提升为 shared abstraction。
- M09 Reaction Sphere、Reaction Map、通用 graph framework 与空间行为均未开始。
- M10 Synthesis、路线搜索和配方推荐均未开始。
- 通用溶解度规则、从分子方程式自动拆解净离子方程式、自动氧化数或氧化还原解释均超出
  当前 M05 最小范围。
