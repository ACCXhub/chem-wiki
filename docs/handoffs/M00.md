# M00 Handoff

## Established

- Node 24/npm 11 的 Vite + React + TypeScript 前端 shell。
- Python 3.13/uv 的 FastAPI 后端，以及独立于数据库的 `GET /health`。
- 官方 PostgreSQL 17 Compose 服务、环境驱动配置、SQLAlchemy engine/session factory 与 Alembic 基线。
- 前端 ESLint/Vitest/build、后端 Ruff/pytest/Alembic 对应的最小 CI。

## Verified evidence

M00 收口验证使用以下命令：

```powershell
npm ci --prefix frontend
npm run lint --prefix frontend
npm run test:run --prefix frontend
npm run build --prefix frontend

docker compose --env-file .env.example up -d --wait postgres
$databaseUrlLine = Get-Content .env.example | Where-Object { $_ -like 'DATABASE_URL=*' }
$env:DATABASE_URL = $databaseUrlLine.Substring('DATABASE_URL='.Length)

uv sync --directory backend --locked --dev
uv run --directory backend ruff check .
uv run --directory backend ruff format --check .
uv run --directory backend alembic upgrade head
uv run --directory backend pytest -q

docker compose --env-file .env.example down
```

收口时前端测试为 `1 passed`，后端测试为 `2 passed`；PostgreSQL healthcheck 为 `healthy`，真实 session 执行 `SELECT 1` 成功，Alembic `upgrade head` 成功。FastAPI 启动后 `/health` 返回 `200 {"status":"ok"}`，Vite 开发服务器可响应 HTTP 请求。

## Boundaries and deferred work

- M00 没有领域实体、业务表、化学模型、前端路由系统、状态管理或 API client。
- FastAPI、SQLAlchemy 与第三方类型不应泄漏进未来领域/application 边界。
- 计算密集能力的 Port 由实际使用方模块定义；没有真实复用时不创建 shared 抽象。
- PostgreSQL 本地 bootstrap 用户不代表生产权限设计；应用/迁移角色拆分推迟到真实 schema 与权限需求出现时。
- 部署、观测和 M01+ 功能均未开始。

## Environment notes

- 本机验证环境为 Windows 11、Docker Desktop 4.87.0、Docker Engine 29.7.2、Compose 5.4.0、PostgreSQL 17.11、Python 3.13.14、uv 0.12.5、Node 24.14.0、npm 11.15.0。
- 新安装的 `uv` 或 Docker Desktop 可能需要新开终端才能刷新 PATH；不要改用系统 `python` alias。
- `.env.example` 仅含本地开发值，不得作为生产凭据。
- `docker compose down` 保留 `chem-wiki_postgres_data` 命名卷；只有明确需要清空本地数据时才移除该卷。
